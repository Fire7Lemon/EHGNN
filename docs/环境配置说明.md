# 环境配置说明

> 适用项目：EHGNN 论文复现项目  
> 推荐分支：`reproduce-baseline`  
> 推荐 Conda 环境名：`ehgnn`  
> 适用场景：本机 Windows 复现、Linux 服务器复现、从 GitHub 重新拉取仓库后重建环境与数据目录

---

## 0. 先说明：clone 仓库不等于环境已经配置好

`git clone` 只会拉取仓库中已经提交的文件，例如代码、脚本、Markdown 文档、`environment.yml`、`requirements-freeze.txt` 等。

它不会自动完成以下事情：

1. 不会自动创建 Conda 环境；
2. 不会自动安装 PyTorch、DGL、torch-scatter 等依赖；
3. 不会把本机已经配好的 `ehgnn` 环境目录复制到服务器；
4. 不会同步 `data/`、`results/`、`logs/`、checkpoint 等大文件目录；
5. 不会自动切换到指定实验分支。

因此，重新部署项目时必须按本文顺序执行：

```text
克隆仓库 → 切换分支 → 创建环境 → 安装 GPU/CPU 依赖 → 准备数据 → 验证环境 → 开始运行
```

## 2. 克隆仓库与切换分支

### 2.1 首次克隆：直接指定分支

如果服务器上还没有项目目录，推荐直接克隆指定分支：

```bash
cd /home
git clone -b reproduce-baseline https://github.com/Fire7Lemon/EHGNN.git EHGNN
cd /home/EHGNN
```

克隆后立即检查当前分支：

```bash
git branch --show-current
```

期望输出：

```text
reproduce-baseline
```

### 2.2 已经克隆过：切换到 reproduce-baseline 分支

如果已经执行过 `git clone`，先进入仓库：

```bash
cd /home/EHGNN
```

查看当前分支：

```bash
git branch --show-current
```

拉取远程分支信息：

```bash
git fetch origin
```

如果本地还没有 `reproduce-baseline` 分支，执行：

```bash
git switch -c reproduce-baseline origin/reproduce-baseline
```

如果本地已经有该分支，执行：

```bash
git switch reproduce-baseline
git pull origin reproduce-baseline
```

再次确认：

```bash
git branch --show-current
git status
```

### 2.3 GitHub 私有仓库认证说明

GitHub 已不支持使用账号密码执行 Git 操作。若仓库是私有仓库，有两种方式：

#### 方式 A：HTTPS + Personal Access Token

```bash
git clone -b reproduce-baseline https://github.com/Fire7Lemon/EHGNN.git EHGNN
```

提示输入密码时，不要输入 GitHub 登录密码，而是输入 GitHub Token。

#### 方式 B：SSH

服务器生成 SSH Key：

```bash
ssh-keygen -t ed25519 -C "Fire7Lemon@github"
cat ~/.ssh/id_ed25519.pub
```

将公钥添加到 GitHub 后测试：

```bash
ssh -T git@github.com
```

再使用 SSH 克隆：

```bash
git clone -b reproduce-baseline git@github.com:Fire7Lemon/EHGNN.git EHGNN
```

## 4. environment.yml 与 requirements-freeze.txt 的定位

### 4.1 environment.yml

`environment.yml` 是 Conda 环境规格文件，用于帮助重建环境。

推荐用法：

```bash
conda env create -f environment.yml
conda activate ehgnn
```

如果 `environment.yml` 中包含 `prefix:`，跨机器使用时可能不需要保留该字段。更推荐维护者导出时使用：

```bash
conda env export --from-history > environment.yml
```

这样文件更干净，更适合跨机器重建。

### 4.2 requirements-freeze.txt

`requirements-freeze.txt` 是 `pip freeze` 的版本快照，主要用于排查差异。

它不等于“一键无脑安装清单”。

尤其是以下包不要盲目照搬：

```text
torch
torchvision
torchaudio
dgl
torch-scatter
torch-sparse
torch-cluster
```

这些包与 Python 版本、CUDA 版本、PyTorch 版本、NVIDIA 驱动有关。

推荐用途：

1. 本机能跑、服务器报错时，对比版本；
2. 记录最终稳定环境；
3. 辅助排查依赖差异。

不推荐在服务器上直接执行：

```bash
pip install -r requirements-freeze.txt
```

除非已经确认其中 GPU 相关 wheel 与服务器完全兼容。

## 6. 安装 PyTorch / DGL / torch-scatter

### 6.1 安装前必须检查

Linux 服务器：

```bash
nvidia-smi
python -V
```

进入环境后：

```bash
conda activate ehgnn
python -V
```

需要确认：

```text
NVIDIA 驱动是否可见
服务器支持的 CUDA 兼容版本
Python 版本
目标 PyTorch 版本
DGL 是否有对应 wheel
torch-scatter 是否有对应 wheel
```

### 6.2 CUDA 12.1 + PyTorch 2.3.1 示例

本项目历史稳定环境中曾使用过：

```text
Python 3.10
PyTorch 2.3.1 + cu121
DGL 2.2.1 + cu121
NumPy 1.26.4
```

示例安装命令如下：

```bash
conda activate ehgnn

python -m pip install torch==2.3.1 torchvision torchaudio \
  --index-url https://download.pytorch.org/whl/cu121

python -m pip install dgl==2.2.1 \
  -f https://data.dgl.ai/wheels/torch-2.3/cu121/repo.html

python -m pip install torch-scatter \
  -f https://data.pyg.org/whl/torch-2.3.1+cu121.html

python -m pip install numpy==1.26.4 scipy scikit-learn pandas tqdm ogb
```

说明：

- 上述命令是项目历史环境的参考组合；
- 若服务器驱动、Python、PyTorch 版本不同，应按实际情况调整；
- 不要混装多个 CUDA 变体，例如同时混入 cu118 和 cu121；
- 遇到 NumPy 2.x ABI 报错时，优先回退到 `numpy==1.26.4`。

### 6.3 CPU 环境说明

如果目标机器没有 GPU，只能安装 CPU 版 PyTorch / DGL。CPU 环境可用于小规模检查，但不适合大规模实验。

## 9. 数据准备

### 9.1 data/ 不随 Git 同步

`data/` 目录通常被 `.gitignore` 忽略，不会随 GitHub 同步。

clone 后如果看不到：

```bash
ls /home/EHGNN/data
```

这是正常现象。

需要单独下载或上传数据。

### 9.2 推荐方式：服务器直接从 Google Drive 下载

项目数据集 Google Drive 文件夹：

```text
https://drive.google.com/drive/folders/186u90Y0gzmdI-R6gQEOis1Nip6G759rv
```

服务器能访问 Google Drive 时，推荐使用 `gdown`：

```bash
conda activate ehgnn
python -m pip install -U gdown

mkdir -p /home/EHGNN/data

gdown --folder "https://drive.google.com/drive/folders/186u90Y0gzmdI-R6gQEOis1Nip6G759rv" \
  -O /home/EHGNN/data \
  --remaining-ok
```

下载完成后检查：

```bash
ls -lh /home/EHGNN/data
```

若下载到压缩包，例如：

```text
DBLP.zip
PubMed.zip
Yelp.zip
```

则进入数据目录解压：

```bash
cd /home/EHGNN/data
unzip DBLP.zip
unzip PubMed.zip
unzip Yelp.zip
```

实际文件名以下载结果为准。

### 9.3 服务器无法访问 Google Drive 时

如果服务器访问 Google Drive 超时，可以使用以下方式。

#### 方式 A：本机上传到服务器

PowerShell：

```powershell
scp -r "D:\procedure\SR\HGNN\EHGNN\data" root@服务器IP:/home/EHGNN/
```

如果是单个压缩包：

```powershell
scp "D:\procedure\SR\HGNN\EHGNN\data\DBLP.zip" root@服务器IP:/home/EHGNN/data/
```

#### 方式 B：WSL + rsync，支持断点续传

```bash
rsync -avhP --append-verify "/mnt/d/procedure/SR/HGNN/EHGNN/data/" \
  root@服务器IP:/home/EHGNN/data/
```

`rsync` 比 `scp` 更适合大文件和长时间传输，因为中断后更容易续传。

#### 方式 C：对象存储中转

对于几十 GB 以上数据，建议：

```text
本机 → OSS/COS/云盘 → 服务器下载
```

比本机直接 `scp` 更稳定。

### 9.4 检查数据目录

常见检查命令：

```bash
cd /home/EHGNN
find data -maxdepth 2 -type d | sort | head -50
find data -maxdepth 2 -type f | sort | head -50
```

按任务检查：

```bash
ls data
ls data/DBLP
ls data/PubMed
ls data/Yelp
```

如果脚本要求的目录名与实际解压目录不一致，应以代码读取路径为准调整目录名，而不是修改大量代码。

## 11. results / logs / checkpoint 不提交

以下内容一般不提交 GitHub：

```text
data/
results/
logs/
*.pt
*.pth
*.ckpt
*.pkl
*.npy
*.npz
__pycache__/
.venv/
.env
```

提交前检查：

```bash
git status --short
git status --ignored --short
```

如果发现大文件被 Git 跟踪，应先停止提交，并检查 `.gitignore`。

若文件已经被 Git 跟踪，仅加入 `.gitignore` 不会自动取消跟踪，需要执行：

```bash
git rm -r --cached data results logs
```

然后再检查：

```bash
git status --short
```

注意：不要误删本地真实数据。`--cached` 表示只从 Git 索引移除，不删除工作区文件。

## 14. 常见问题

### 14.1 conda activate ehgnn 失败

说明目标机器上还没有创建该环境，先执行：

```bash
conda create -n ehgnn python=3.10 -y
conda activate ehgnn
```

或使用：

```bash
conda env create -f environment.yml
```

### 14.2 git clone 后没有 data/

正常。`data/` 不随 Git 同步，需要单独下载或上传。

### 14.3 git clone 后不是 reproduce-baseline 分支

手动切换：

```bash
cd /home/EHGNN
git fetch origin
git switch reproduce-baseline
```

如果本地不存在：

```bash
git switch -c reproduce-baseline origin/reproduce-baseline
```

### 14.4 GitHub 要求输入密码但失败

GitHub 不支持账号密码做 Git 认证。使用：

```text
Personal Access Token
```

或配置 SSH Key。

### 14.5 import torch 成功，但 torch.cuda.is_available() 是 False

检查：

```bash
nvidia-smi
python -m pip list | grep torch
```

常见原因：

```text
安装了 CPU 版 PyTorch
服务器没有正确识别 NVIDIA 驱动
CUDA wheel 与环境不匹配
当前 Python 不是 ehgnn 环境
```

### 14.6 DGL 或 torch-scatter import 失败

优先确认三者匹配：

```text
PyTorch 版本
CUDA 变体
DGL wheel
torch-scatter wheel
```

查看：

```bash
python -m pip list | grep -E "torch|dgl|scatter"
```

不要随意混装 cu118、cu121、cpu 版本。

### 14.7 NumPy 相关 ABI 报错

如果遇到类似 NumPy 2.x ABI 不兼容的错误，优先尝试：

```bash
python -m pip install "numpy==1.26.4"
```

然后重新运行验证脚本。

### 14.8 scp 很慢

`scp` 速度取决于本机上传带宽和线路质量，不代表服务器带宽跑满。

更推荐：

```text
服务器直接下载数据
rsync 断点续传
对象存储中转
```
